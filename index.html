MODEL NOTES · SOURCES

A useful bound.
Not a benchmark.

The Roofline model connects peak compute, memory bandwidth, and operations per byte. It is a useful lens, not a prediction of real-world token throughput.

ATTAINABLE PERFORMANCE
Pattainable = min [ Ppeak, BW × I ]

I = operations / byte · BW = bandwidth at the stated memory level

01

Precision is not interchangeable

FP4, BF16, INT8, and FP16 peaks use different operations and cannot be ranked together.

02

Capacity is not bandwidth

Fit is a weight estimate with a generic reserve; KV cache and workspace are excluded.

03

A peak is not a measurement

Cache, kernel shape, runtime, interconnect, and power can change observed performance.

Sources, assumptions, and limits ＋

Hardware references

Each profile identifies scope, memory level, and evidence. “Derived” means a unit conversion or per-device division from a vendor system total; a vendor claim is not an independent measurement.

  • Apple — M4 Pro and M4 Max
  • Apple — M5 Pro and M5 Max
  • Intel ARK — Core Ultra 9 285K
  • AMD — Ryzen 9 9950X
  • NVIDIA — DGX B200 system totals
  • Google Cloud — TPU v6e
  • Groq — What is a Language Processing Unit?

Workload assumptions

  • Two operations per MAC; weights are fetched once and reused across the batch/prompt.
  • Weight estimate: parameters × bits / 8; working set: weights × 1.20.
  • Decode uses one token per step; prefill uses the selected prompt length.
  • Attention, KV traffic, scales, dequantization, activations, kernels, and data transfers are excluded.
  • Intel/AMD bandwidths are theoretical DDR limits. B200 per-GPU values are derived from an eight-GPU DGX system.
  • Groq’s source claims over 80 TB/s SRAM bandwidth but does not state usable capacity; fit remains Unknown.
